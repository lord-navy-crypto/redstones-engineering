# Validation Plant v1.1 Design

## Goal

Turn the current Integrated Validation Plant from a functional commissioning scaffold into a complete, readable in-world industrial validation hall without changing the existing A→F DUT semantics or the 19 component self-tests.

## Scope

v1.1 is a structural/readability release. It keeps the current validation runtime model: the validator may own test stimulus, phase progression, fixture placement, and WAIT/PASS/FAIL panel power; DUT verdicts still come from live world/block/runtime evidence. A later v2 will replace selected backend-driven phase stimulus with explicit in-world redstone/control wiring.

## Required plant structure

The plant remains modular and keeps the six functional cells:

- A Acquisition — reference source, probe, oscilloscope, instrument path.
- B Conditioning — gain conditioner, precision filter, saturation behavior.
- C Instrumentation — inline analyzer and independent readback.
- D Control — analog command backbone and PWM diagnostic branch.
- E Safety/Fault — fault injector, safety interlock, alarm lifecycle.
- F Process — servo actuator, position sensor, process/permit observation.

The existing 3-block gap between the control room and the top cell row becomes a dedicated `service_spine` module so there is no unexplained empty strip in the facility.

Every Cell module must provide:

1. full-volume air clearing so stale terrain/blocks cannot remain inside the template volume;
2. a finished floor and cell-color border;
3. vertical corner columns and upper frame/header beams;
4. visible maintenance/access openings rather than an accidental empty shell;
5. industrial lighting and equipment-side walkable space;
6. a local WAIT/PASS/FAIL panel with a yellow/lime/red concrete color base under the corresponding lamp;
7. readable signs identifying the Cell, what it tests, and the expected evidence;
8. the existing real DUT signal path unchanged unless a structural conflict requires an explicitly tested adjustment.

The control room must provide:

- a completed floor/frame/wall system;
- a readable master legend (`WAIT/YELLOW`, `PASS/GREEN`, `FAIL/RED`);
- readable per-cell status labels A–F;
- a diagnostic sign telling the tester to use `plant status` and report phase/cell/detail;
- the existing MASTER RETEST control.

## Sign/NBT support

`tools/rse_validation_factory.py` must support structure-template block entries containing block-entity NBT. A sign placement is represented as a normal palette block plus a block-entry `nbt` compound. The supported NBT encoder only needs the types required by signs and current validation assets: compound, byte/bool, int, string, list-of-string, and list-of-compound/int where already supported.

Standing signs use Minecraft 1.21.1 sign block-entity fields:

- `id = minecraft:sign`
- `front_text` and `back_text`
- four JSON text messages per side
- `color`
- `has_glowing_text`
- `is_waxed`

Signs are generated by a reusable helper in `rse_validation_plant.py`; callers provide up to four short lines.

## Status readability contract

A redstone lamp alone is not a color indication. Every status lamp must have an unambiguous colored base directly below it:

- WAIT lamp base: `minecraft:yellow_concrete`
- PASS lamp base: `minecraft:lime_concrete`
- FAIL lamp base: `minecraft:red_concrete`

The local and master panels also carry text labels, so a tester can report the exact state without guessing from lamp location.

## Diagnostic text contract

Cell signs use concise, stable wording:

- A: `CELL A / ACQUISITION / SOURCE + PROBE / EXPECT 6 VALID`
- B: `CELL B / CONDITIONING / GAIN x2 + FILTER / SATURATION TEST`
- C: `CELL C / INSTRUMENT / INLINE ANALYZER / READBACK CHECK`
- D: `CELL D / CONTROL / PWM BRANCH / ACTIVITY CHECK`
- E: `CELL E / SAFETY + FAULT / INTERLOCK + ALARM / TRIP RECOVER`
- F: `CELL F / PROCESS / SERVO + SENSOR / FEEDBACK CHECK`

The control room includes a reporting sign: `DIAGNOSTICS / RUN plant status / REPORT PHASE / CELL + DETAIL`.

## Acceptance tests

`tools/test_rse_validation_plant.py` must fail if any of the following regress:

- service spine missing or offsets overlap;
- a Cell lacks high-level frame blocks at y=4;
- a Cell lacks corner columns;
- a local/master status lamp lacks the correct colored base;
- Cell identity signs are absent;
- sign block-entity NBT is not emitted into structure bytes;
- control-room diagnostic/legend signs are absent;
- the original DUT blocks disappear;
- the existing 19 small self-tests are repurposed.

## Non-goals for v1.1

- No new DUT family.
- No AMR/operations expansion.
- No replacement of the current acceptance phase engine with physical redstone sequencing.
- No claim that v1.1 is a pure-redstone factory acceptance rig.
